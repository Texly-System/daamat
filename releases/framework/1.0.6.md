# @damatjs/framework 1.0.6

> Provider loading uses the same strict entry rule as installer resolution.

## Changed / improved

- Bare-source provider directories are ignored during heuristic resolution when
  they lack `index.ts` or `index.js`, allowing module-local fallbacks.
- Workflow, job, event, and pipeline providers continue to support direct files
  and conventional directory entries.
- Explicit manifest provider paths remain authoritative and fail startup with a
  provider-specific error when invalid.
- Direct acceleration projection and audit SQL now uses fully qualified
  relations in the dedicated `damat` PostgreSQL schema.
- The Hono dependency now requires 4.12.34 or newer within the supported 4.x
  range.

## Operations

Run system migrations before startup. Runtime database roles need `USAGE` on
`damat` and the table privileges required by enabled durable services.

## Action required

Run the complete system migration catalog before startup. Grant separate
runtime roles `USAGE ON SCHEMA damat` and the required table privileges.
