# @damatjs/pipelines 1.0.6

> Clarifies and regression-locks the activation boundary for durable event waits.

## What changed

`event.wait` history begins at the creation of its node execution. Matching
events published earlier are excluded even when their correlation ID matches.
Signals remain separately buffered and may arrive before their wait node is
active. The package documentation now shows the safe fork/pre-arm, work,
correlated completion event, and `all`-join pattern.

## Added

- PostgreSQL-backed regressions for the activation boundary and pre-armed
  correlated event-wait graph.
- Ordered migration `003` relocates all pipeline infrastructure relations into
  the dedicated `damat` PostgreSQL schema.

## Changed / improved

- Current event matching semantics are documented consistently across the
  package README, internals guide, and Damat Guide.
- Runtime, inspection, retention, trigger, and test SQL uses qualified Damat
  relation names and no longer depends on `search_path`.

## Operations

Run system migrations before starting pipeline workers. Runtime database roles
need `USAGE` on `damat` and the required table/sequence privileges.

## Action required

Run the complete system migration catalog before startup and grant runtime
roles access to the `damat` schema. Event-wait matching behavior itself is
unchanged.
