# @damatjs/pipelines 1.0.4

> Pipeline idempotency keys now bind to canonical run-start intent.

## Changed / improved

- Pipeline run rows persist an intent fingerprint.
- A reused key conflicts when the definition, version, input, or persisted start intent differs.
- Append-only system migration `002` adds fingerprint storage.

## Breaking

- Legacy rows without a verifiable fingerprint cannot replay under the same idempotency key.

## Action required

Run `bun run db:migrate` before starting pipeline clients or workers.
