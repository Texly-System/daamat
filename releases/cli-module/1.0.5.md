# @damatjs/cli-module 1.0.5

> Module source capabilities install into their backend-owned roots.

## What changed

The broad module source mapping could absorb overlapping routes, workflows,
jobs, events, and pipelines. Legacy or receiver-free fallback destinations also
placed these capabilities inside the module directory. Module installation now
routes narrow capabilities first and uses the conventional top-level backend
destinations by default.

## Changed / improved

- Routes, workflows, jobs, events, pipelines, and links install under their
  matching `src/<capability>/<module-id>` roots.
- Module tests default to `tests/modules/<module-id>`.
- The remaining implementation stays under `src/modules/<module-id>`.

## Breaking

- None for correctly split installations. Reinstalling an affected module may
  relocate files that were previously captured by the broad module mapping.

## Action required

Run `damat module plan <source>` and review the corrected destinations before
updating or reinstalling an affected module.
