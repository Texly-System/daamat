# @damatjs/orm-migration 1.0.6

> Migration generation carries native pgvector requirements through snapshots
> and rendered SQL files.

## Added

- Migration preflight creates the dedicated `damat` schema and atomically
  relocates an existing `public._damat_migration_logs` table before reading its
  history.
- Initial and incremental generation now emits `CREATE EXTENSION IF NOT EXISTS
  vector` before tables that use `VECTOR(n)` or `HALFVEC(n)`.
- Snapshot normalization persists inferred extension requirements, making a
  second generation against unchanged models a no-op.
- End-to-end generator coverage verifies extension ordering, exact HALFVEC DDL,
  HNSW operator classes, SQL statement delimiters, and manual-review snapshot
  advancement.

## Changed

- Tracker reads and writes use `damat._damat_migration_logs`.
- Legacy immutable system migrations run with a transaction-local compatibility
  search path; current runtime SQL remains fully qualified.
- Generated `.sql` files continue to append semicolons to processor statements;
  the processor APIs remain delimiter-free for composition.

## Compatibility note

- This package follows the ORM 1.0.6 native pgvector contract. Existing
  `columns.vector()` snapshots require an application-reviewed data migration.

Run `bun run db:migrate` before starting 1.0.6 API or worker processes. If both
public and `damat` tracker tables exist, migration stops with reconciliation
guidance rather than choosing one history. An existing `damat` schema must be
controlled by the migration role and contain only Damat-owned relations.
