# @damatjs/services 1.0.6

## Added

- Generated CRUD validates native `vector` and `halfvec` writes before SQL.
  Values must be finite numeric arrays with exactly the model column's
  declared dimensions. `create`, `createMany`, `update`, `updateOne`,
  `upsert`, and `upsertMany` use the same validation path.
- Nullable and default-backed vector columns retain their existing omitted and
  `null` behavior. Ordinary PostgreSQL arrays are unchanged.

## Internal

- `ModelMethods` was split into responsibility-focused modules while keeping
  the public CRUD surface and transaction/cascade behavior intact.

## Upgrade notes

The `columns.vector()` semantic change is part of the coordinated 1.0.6 release:
it now describes native pgvector storage rather than `REAL[]`. Review existing
data and snapshots before upgrading; install the `vector` extension through the
ORM migration flow and plan any application-reviewed data conversion.
